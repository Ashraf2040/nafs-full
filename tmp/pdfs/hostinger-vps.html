النشر على VPS من Hostinger

لقد أرسلت لك الكود كاملاً. أرجو نشر التطبيق وقاعدة البيانات على VPS الخاص بي كما يلي:

  1. اسم التطبيق وإعداد الخادم: اجعل الاسم الظاهر في الموقع وعنوان المتصفح Daily Lesson Plan. ثبّت Ubuntu 24.04 مع CloudPanel على VPS، وأنشئ موقع Node.js للنطاق.
  2. قاعدة البيانات: ثبّت PostgreSQL على الـ VPS، وأنشئ قاعدة ومستخدم تطبيق بصلاحيات محدودة. اجعل اتصال PostgreSQL محلياً فقط وأبقِ المنفذ 5432 مغلقاً للعامة. خذ نسخة احتياطية من قاعدة البيانات الحالية وانقلها إلى قاعدة VPS الجديدة حتى لا نفقد الاختبارات والمستخدمين.
  3. الكود: ارفع المستودع الخاص إلى مجلد الموقع، وثبّت الحزم بـ npm ci ثم ابنِ التطبيق بـ npm run build. شغّله عبر PM2 باسم daily-lesson-plan على منفذ CloudPanel، واجعل PM2 يعيد تشغيله عند إعادة تشغيل الخادم.
  4. الإعدادات: اضبط DATABASE_URL للاتصال المحلي بقاعدة VPS، وNEXTAUTH_URL للنطاق عبر HTTPS، وNEXTAUTH_SECRET وGEMINI_API_KEY وGOOGLE_CLIENT_ID وGOOGLE_CLIENT_SECRET. أضف Google OAuth callback: https://نطاقي/api/auth/callback/google. لا تحفظ الأسرار في Git.
  5. Prisma: بعد أخذ نسخة احتياطية والتأكد من استعادة قاعدة البيانات، شغّل npx prisma migrate deploy. لا تستخدم prisma migrate reset.
  6. الصور والملفات: انقل مجلد public/image-source كاملاً إلى الموقع على الـ VPS؛ به نحو ١٬٢٨٥ صورة وحجمه قرابة ٢٫٥ غيغابايت، وهو غير محفوظ في Git. أبقه في مسار دائم لا تحذفه تحديثات الكود. اجعل ملفات الأدلة الدراسية والصور المرفوعة تحفظ في تخزين دائم كذلك.
  7. النطاق والأمان: وجّه سجل A للنطاق إلى IP الخاص بالـ VPS، وفعّل شهادة Let's Encrypt من CloudPanel. اسمح فقط بالمنافذ اللازمة مثل SSH وHTTP وHTTPS، ولا تفتح PostgreSQL للإنترنت.
  8. الفحص: اختبر دخول الطالب والمعلم والمدير، وافتح اختباراً بصور، وجرّب رفع ملف، وتأكد من بقاء الصور والملفات بعد إعادة تشغيل التطبيق.
مهم: يتضمن الكود إصلاح مسارات الصور النسبية. أرجو نشر هذا التعديل والتأكد من أن روابط الصور تعمل بعد نقل المجلد.

Deploy on a Hostinger VPS

I have already shared the complete source code with you. Please deploy the app and database on my VPS as follows:

  1. App name and server: Set the visible website branding and browser title to Daily Lesson Plan. Install Ubuntu 24.04 with CloudPanel on the VPS and create a Node.js site for my domain.
  2. Database: Install PostgreSQL on the VPS and create an app database with a restricted app user. Keep PostgreSQL local-only and do not expose port 5432 publicly. Back up the current database and restore it to the new VPS database so we keep the existing quizzes and users.
  3. Code: Upload the private repository to the site directory, install dependencies with npm ci, and build with npm run build. Run it under PM2 as daily-lesson-plan on the CloudPanel port, and configure PM2 to restart it when the VPS reboots.
  4. Environment: Set DATABASE_URL to the local VPS database, NEXTAUTH_URL to my HTTPS domain, plus NEXTAUTH_SECRET, GEMINI_API_KEY, GOOGLE_CLIENT_ID, and GOOGLE_CLIENT_SECRET. Add the Google OAuth callback https://my-domain/api/auth/callback/google. Keep secrets out of Git.
  5. Prisma: After backing up and restoring the database, run npx prisma migrate deploy. Do not run prisma migrate reset.
  6. Images and files: Copy the complete public/image-source folder to the VPS site; it has about 1,285 images and is roughly 2.5 GB, and is not tracked in Git. Keep it in a persistent location that code updates will not remove. Store study-guide uploads and generated images persistently too.
  7. Domain and security: Point the domain's A record to the VPS IP and enable a Let's Encrypt certificate in CloudPanel. Allow only required ports such as SSH, HTTP, and HTTPS; do not expose PostgreSQL to the internet.
  8. Verify: Test student, teacher, and admin sign-in, open a quiz with images, test a file upload, and confirm files remain available after restarting the app.
Important: The source includes a fix for relative image paths. Please deploy that change and verify image URLs after copying the folder.
